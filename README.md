# UPI Fraud Intent Firewall

A **research prototype** for context-aware, pre-authorisation digital-payment fraud detection. The system is designed to distinguish legitimate unusual payments—such as a long-distance auto-rickshaw ride, emergency hospital payment, first rent payment, or a genuine high-fan-in merchant—from socially engineered payments, account takeover and mule-directed transfers.

> This repository is an educational/research implementation. It is not a banking product, does not connect to NPCI or a real UPI switch, and must not be used to make real financial decisions without security review, regulatory approval, representative data and controlled validation.


## Multi-source workflow

The recommended workflow now uses **PaySim + BankSim + IBM AML HI-Small/LI-Small** with separate canonical and stage-specific data products. Follow [`docs/MULTISOURCE_RUNBOOK.md`](docs/MULTISOURCE_RUNBOOK.md). The legacy `src.data.prepare_dataset` command remains only for the original one-source demo; the complete model now uses `src.data.prepare_multisource`.

## What is implemented

### Fast pre-authorisation path

- Rule engine with both risk rules and protective rules
- Robust statistical anomaly features and rolling velocity features
- LightGBM transaction-risk model
- Separate legitimate-novelty/context model
- Device/session and geospatial journey features
- Cached graph and sequence intelligence from Redis

### Near-real-time intelligence path

- Compact time-aware Transformer for user/session event sequences
- Three heterogeneous graph views: money flow, identity/device, and context/trust
- Heterogeneous Graph Transformer (HGT) snapshot encoders
- Typed temporal event-memory model (`hetero_tgn.py`), a bounded TGN-style research implementation
- Multi-view attention to combine the three graph views
- Recipient-archetype learning to distinguish merchants/gig workers from mules
- Graph-embedding anomaly detector

### Asynchronous intelligence and operations

- Optional OpenAI Structured Outputs complaint extractor
- Local rule-based complaint extractor fallback
- Mixture-of-experts fusion model
- Prediction uncertainty and calibrated policy actions
- Kafka transaction/telemetry/feedback streams
- Redis rolling online feature store
- FastAPI scoring service
- Streamlit investigator dashboard
- Android telemetry demo client
- Prometheus metrics and MLflow-ready project structure

## Important implementation boundaries

1. **No public labelled UPI dataset is assumed.** PaySim can be downloaded, but the repository also generates its own deterministic PaySim-like base table and then injects UPI-specific fraud and hard-negative scenarios.
2. **The temporal graph model is a functional prototype, not a distributed industrial TGN.** It uses typed event messages, temporal ordering and evolving entity representations, while remaining small enough to train locally.
3. **Android remote-access and overlay indicators are demonstration inputs.** An ordinary app cannot reliably inspect every other app. The demo therefore collects legitimate app/session telemetry and exposes simulated toggles for those signals.
4. **The LLM is asynchronous.** It structures complaints and analyst notes; it never directly approves or blocks a payment.

## Recommended machine

- Python 3.11 or 3.12, 64-bit
- 16 GB RAM minimum; 32 GB is preferable for the full graph pipeline
- Docker Desktop for Kafka and Redis
- NVIDIA GPU optional; the default 30,000-row demo can run on CPU, but advanced training will be slower
- Android Studio with JDK 17 for the optional Android client

## 1. Installation

### Windows PowerShell

```powershell
cd upi-fraud-intent-firewall
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

Install PyTorch first using the command generated by the official PyTorch selector for your CPU or CUDA setup. Then run:

```powershell
pip install -r requirements.txt
Copy-Item .env.example .env
```

### macOS/Linux

```bash
cd upi-fraud-intent-firewall
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
# Install PyTorch using the official CPU/CUDA command first.
pip install -r requirements.txt
cp .env.example .env
```

Validate the environment:

```bash
python -c "import torch, torch_geometric, lightgbm, pyarrow; print(torch.__version__)"
python -m compileall src
```

Run the fast in-memory smoke test before installing infrastructure:

```bash
python scripts/smoke_test.py
```

## 2. Download and prepare the multi-source data

The recommended pipeline uses PaySim, BankSim and IBM AML HI-Small/LI-Small. Configure Kaggle, then run:

```bash
python scripts/download_data.py all
python scripts/verify_multisource_data.py
python -m src.data.prepare_multisource \
  --paysim-rows 30000 \
  --banksim-rows 30000 \
  --ibm-negative-ratio 10 \
  --ibm-max-negatives-per-file 20000
```

The command writes separate canonical source tables and stage-specific products. See [`docs/MULTISOURCE_RUNBOOK.md`](docs/MULTISOURCE_RUNBOOK.md) for the complete explanation and scale-up guidance.

## 5. Train all models

Local/rules-based complaint extraction:

```bash
python -m src.training.train_all --skip-prepare
```

Optional external LLM extraction:

1. add `OPENAI_API_KEY` to `.env`;
2. keep or change `OPENAI_MODEL`;
3. run:

```bash
python -m src.training.train_all --skip-prepare --use-llm
```

The training command runs these stages in order:

1. LightGBM transaction fraud model
2. LightGBM legitimate-novelty model
3. Time-aware sequence Transformer
4. Three HGT graph-view encoders
5. Multi-view graph attention
6. Typed temporal event-memory model
7. Graph anomaly detector
8. Complaint/scam intelligence extraction
9. Mixture-of-experts fusion
10. Uncertainty estimation and policy actions

Model artifacts are written under `models/`; aggregate metrics are written to `models/metrics.json`.

For a faster smoke test, first set `DEMO_ROWS=5000` in `.env` and reduce epochs in `configs/model_config.yaml` or the training module calls.

## 11. Android client

Open `android-client/` in Android Studio, allow Gradle sync, and run on an emulator or device. When using the Android emulator, use `http://10.0.2.2:8000` as the API URL. A physical device must use the development computer's LAN IP and allow cleartext development traffic or HTTPS as appropriate.

The Android demo sends:

- telemetry events to `/telemetry`;
- recipient checks to `/precheck`;
- final scoring requests to `/score`.

See [`android-client/README.md`](android-client/README.md).

## 12. Run tests


## 13. Evaluation

```bash
python -m src.training.evaluate
```

The evaluation focuses on:

- PR-AUC and ROC-AUC;
- false-positive rate on legitimate-novelty scenarios;
- fraud-type recall;
- action distribution;
- mandatory edge-case behaviour;
- calibration and uncertainty;
- model ablations.

## API endpoints

| Endpoint | Purpose |
|---|---|
| `POST /telemetry` | Store app/session telemetry |
| `POST /precheck` | Check recipient/QR risk before amount confirmation |
| `POST /score` | Full pre-authorisation decision |
| `POST /complaint` | Structure complaint text and update recipient intelligence |
| `POST /feedback` | Store confirmed outcome/analyst feedback |
| `GET /transaction/{id}` | Retrieve a previous decision |
| `GET /entity/{type}/{id}` | Inspect cached entity risk/features |
| `GET /health` | Service and model status |
| `GET /metrics` | Prometheus metrics |

## Research question implemented by this repository

> Can a context-aware, uncertainty-calibrated, dual-speed pre-authorisation fraud system reduce false positives on legitimate first-time/unusual payments while retaining detection of socially engineered and mule-directed transfers?
