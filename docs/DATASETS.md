# Data sources and acquisition guide

There is no widely available, representative, labelled, production UPI transaction dataset with device, session, recipient-network, complaint and geospatial signals. Real payment data is restricted for privacy, security and regulatory reasons. This repository therefore uses a **composite research dataset strategy**.

## Recommended data plan

| Priority | Dataset | Best use in this project | Main limitation |
|---|---|---|---|
| 1 | PaySim | Transaction baseline, class imbalance, transfer/cash-out structure | Mobile-money simulator, not UPI-specific |
| 2 | Your synthetic UPI augmentation | QR, collect requests, devices, telemetry, location, hard negatives and social-engineering labels | Synthetic assumptions must be documented |
| 3 | IBM AML-Data / AMLSim | Mule, structuring, layering and laundering-flow patterns | AML rather than instant UPI authorisation |
| 4 | IEEE-CIS Fraud Detection | Device, identity and transaction-feature engineering ideas | E-commerce/card context, not UPI |
| 5 | Elliptic++ | Temporal money-flow graph and illicit-actor modelling | Cryptocurrency domain |
| 6 | DGraphFin | Large-scale dynamic graph anomaly benchmarking | Its relationships are not UPI payment edges |
| 7 | BankSim | Merchant/customer hard-negative and category behaviour | Synthetic card/payment setting |

## 1. PaySim — primary base dataset

- Kaggle dataset: https://www.kaggle.com/datasets/ealaxi/paysim1
- Original paper: https://www.msc-les.org/proceedings/emss/2016/EMSS2016_249.pdf
- Licence shown by Kaggle: CC BY-SA 4.0

The Kaggle data is a scaled synthetic dataset generated by PaySim from aggregated patterns based on one month of mobile-money logs. Use it for transaction amount, sender, receiver, transaction type, time steps and fraud imbalance.

### Download with this repository

```bash
python scripts/download_data.py paysim
```

Or download manually and place the main CSV at:

```text
data/raw/PS_20174392719_1491204439457_log.csv
```

### Leakage warning

The PaySim data card warns that fraud transactions are cancelled and that balance columns can reveal this process. Do not use post-outcome balance fields as pre-authorisation features without a careful leakage analysis. This repository retains them in the raw table but excludes them from the primary online feature lists.

## 2. IEEE-CIS Fraud Detection

- Competition/data page: https://www.kaggle.com/competitions/ieee-fraud-detection/data

Use this as a reference for:

- transaction/device table joins;
- device/browser identity features;
- missing-value handling;
- entity aggregation;
- time-based validation.

Do not merge its fraud labels directly with PaySim rows as though they came from the same distribution. Instead, borrow feature-engineering patterns or train a separately evaluated expert.

## 3. IBM AML-Data and AMLSim

- Generated data: https://github.com/IBM/AML-Data
- Simulator: https://github.com/IBM/AMLSim

Use these resources for:

- fan-in/fan-out and rapid pass-through motifs;
- structuring and layering patterns;
- multi-hop money-flow graphs;
- mule-network scenario generation;
- graph algorithm validation.

The data is fully synthetic and carries its own data licence. Review the repository licence before redistribution.

## 4. Elliptic++

- Repository: https://github.com/git-disl/EllipticPlusPlus
- Paper: https://arxiv.org/abs/2306.06108

Use it for:

- temporal transaction graphs;
- transaction-level versus actor-level labels;
- connected illicit-entity detection;
- experiments with time-aware graph encoders.

Its cryptocurrency setting differs materially from UPI, so results should be reported as transfer-learning or architecture benchmarking—not UPI accuracy.

## 5. DGraphFin

- Project page: https://dgraph.xinye.com/
- PyTorch Geometric dataset documentation: https://pytorch-geometric.readthedocs.io/en/latest/generated/torch_geometric.datasets.DGraphFin.html
- Paper: https://arxiv.org/abs/2207.03579

Use it for:

- scalable imbalanced node classification;
- dynamic graph experiments;
- graph sampling and generalisation tests.

Its edges should not be described as UPI transfers. Treat it as a large financial-domain graph benchmark.

## 6. BankSim

- Kaggle: https://www.kaggle.com/datasets/ealaxi/banksim1

Use it to enrich merchant/customer behaviour and merchant-category hard negatives. It is especially useful for studying legitimate high-frequency merchant activity.

## 7. Complaint/scam-language data

No raw real customer complaints are included. The repository generates synthetic complaints with controlled labels using:

```bash
python -m src.simulation.generate_complaints
```

The optional LLM component structures these texts into fields such as scam type, communication channel, QR/collect mention, urgency and remote-access mention. For actual research involving real complaints, obtain ethics/privacy approval and remove direct identifiers before processing.

## 8. Geospatial and device data

The synthetic generator creates privacy-preserving location/context features. The Android demo can send a current coarse location and app/session telemetry from the user's own device. It does not scrape other apps or access protected bank data.

## Recommended final dataset composition

For the first complete experiment:

```text
30,000–100,000 PaySim/synthetic base transactions
+ 20–30% deliberately generated legitimate novelty
+ 10–20% socially engineered scenarios
+ simulated mule subgraphs and rapid pass-through paths
+ event sequences for each transaction
+ synthetic complaint descriptions
```

The scenario mix in this repository is deliberately much more balanced than real fraud prevalence so every expert can train in a small prototype. For final reporting, evaluate again on a realistic low-prevalence test distribution and report precision/recall at operational false-positive rates.
